SSH honeypot and threat intelligence dashboard

Oct 2026 to present

A Cowrie SSH honeypot running on an AWS EC2 server (Ubuntu 24.04), live since 16 October 2026. It acts like a real server so I can record what attackers try. Three scanners found it within the first hour, and by day 10 it was getting around 60 different IPs a day.

What it has caught so far

  • Password guessing with default logins for specific devices, like pi/raspberry (Raspberry Pi), nvidia/nvidia (Jetson boards) and firedancer/firedancer (Solana crypto nodes)
  • A recon script that checked the CPU, GPU and uptime, then tested if it could create and run a file. It looked like it was deciding if the server was worth crypto mining on, and whether it was a honeypot
  • The same odd command (/bin/./uname -s -v -n -r -m) from 5 different IPs, and the same file hash from 2 different IPs, which links them to the same tool
  • One IP coming back on 4 of 5 days, always as root, with a new random password each time
  • A packed Linux malware sample downloaded with bash's /dev/tcp instead of wget or curl. I kept the SHA256 hash only and never opened the file

What I did

  • Locked down my own access first: SSH keys only, a private port open only to my home IP, and root login turned off
  • Set firewall rules in an AWS security group and ufw, with ufw redirecting port 22 to Cowrie
  • Ran Cowrie as a systemd service under its own user with no sudo rights
  • Turned on two-step login for AWS and GitHub and set up a zero-spend billing alert
  • Wrote Bash scripts that summarise each day's connections, logins, commands and saved files, and mask the attackers' IPs so the output is safe to share
  • Read the logs with grep and jq and mapped what I saw to MITRE ATT&CK techniques in a daily devlog

Still working on

  • A Python pipeline with SQLite, IP locations, AbuseIPDB, VirusTotal hash checks and MITRE ATT&CK mapping
  • A Streamlit dashboard and a "30 days of attacks" report, due by 24 Nov 2026
  • Sigma detection rules, and later turning it into an open-source Cowrie log analyser

Small office network in Cisco Packet Tracer

A small office network built in Cisco Packet Tracer with a router, two switches, a server, PCs, a printer and a Wi-Fi access point with laptops.

What I did

  • Connected a Cisco 2911 router to two 2960 switches, with the server, printer and PCs on one switch and more PCs and the Wi-Fi access point on the other
  • Split the network into VLANs (10, 20, 30, 40 and 99) and set a switch port to trunk mode so it carries all of them
  • Set up DHCP so the PCs get their addresses automatically, and gave the server a fixed (static) address
  • Tested the connections with ping

Super iMac: a MacBook Pro inside a 2009 iMac

Fitting a 16-inch M2 Pro MacBook Pro logic board into a 2009 27-inch iMac (A1312) case to make an all-in-one. The iMac keeps its aluminium body, front glass, original LG LM270WQ1 screen, speakers and stand.

What I've done

  • Tested the donor MacBook before taking it apart: it powered on normally, showed the M2 Pro, 16GB RAM and 512GB SSD, and Wi-Fi, Bluetooth and all three USB-C ports worked
  • Planned the whole build on a whiteboard: which iMac parts stay, how the picture gets from the MacBook board to the iMac screen, and how air flows through the case
  • Designed a mounting plate for the logic board: 3mm PETG, four M3 standoffs 8mm high, ±0.5mm tolerance

Still working on

  • Connecting the original iMac screen to the MacBook board through an LCD controller board
  • Working out power, USB, cooling and mounting inside the case
